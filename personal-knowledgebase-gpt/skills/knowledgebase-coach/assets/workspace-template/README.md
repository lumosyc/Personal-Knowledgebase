# Personal Knowledgebase — GPT / Codex 桌面版

一个以本地文件为长期记录的个人研究与学习系统。你提供论文、课程材料和研究想法，GPT 在 Codex 中整理知识库，再通过苏格拉底、费曼和练习反馈帮助你理解与内化。Obsidian 可以打开同一文件夹，用来阅读、编辑和查看笔记关联。

本版由 Erber 的 Personal-Knowledgebase（Claude Code 版）迁移而来，保留原版四层路径与教学协议，将手工修改个人信息改成问答初始化。问答设计借鉴 prompt-clarifier：只问影响当前任务的缺口、复用已知信息、允许跳过，并随学习逐步完善。

**复核结论：原版功能定义、页面模板和学习路径已完整迁移；没有发现功能模块被删除。** 这不代表 GPT 与 Claude 每轮对话、解题正确率和教学效果完全相同。详细对应与适配差异见 [功能复核报告](meta/compatibility_audit.md)，实际测试范围见 [验证记录](meta/validation.md)。

## 1. 先用起来

### 方式 A：直接打开配套知识库

1. 将完整包解压到长期保存的位置。
2. 在 Codex 桌面添加本地项目，选择**本文件夹**。
3. 在这个项目中新建聊天，发送：

   > 开始学习。先通过提问了解我的背景、目标和学习偏好，每次只问一个问题。不确定的内容允许跳过，并自动保存到这个知识库。

4. 回答短问题，然后进入首次学习或诊断。以后在同一项目说“继续上次学习”。

该文件夹已经包含工作区指令与项目技能，可以直接使用；无需手工填写 PERSONALIZE.md、AGENTS.md 或画像文件。运行需要 Codex 有权读取和写入这个文件夹。画像保存助手使用 Python 3.10+，只依赖标准库；没有 Python 时，技能提供通过 Codex 文件工具保存的替代流程。

### 方式 B：安装为可重复调用的桌面插件

全局安装脚本在完整发行包的上一级目录；在该解压目录的 PowerShell 中执行：

```powershell
./install-plugin.ps1
```

脚本会注册本包内的本地插件源，并安装 `personal-knowledgebase-gpt@knowledgebase-local`。它不调用额外模型 API，不需要另填 API key；你仍通过自己的 Codex 账户使用模型。

若找不到 Codex CLI，可以指定它的实际路径：

```powershell
./install-plugin.ps1 -CodexPath '你的 Codex CLI 的实际绝对路径'
```

若系统阻止执行脚本，可使用方式 A，或让 Codex 读取脚本并执行其中两个安装调用；不必修改系统执行策略。安装后如技能未出现，重新打开项目或重启 Codex。保留 `marketplace` 文件夹供后续更新。

安装后，在想使用的本地项目里说“初始化我的知识库”。插件会把学习记录放进项目工作区；**插件缓存和模板不是个人数据目录**。当前包只完成了隔离配置中的安装验证，尚未替你修改当前账户的插件配置。全局插件与项目技能同时存在时可能显示同名入口，优先使用项目内版本，不要同时运行两个保存流程。

## 2. 问答初始化会做什么

按当前任务需要，逐步了解：

- 最近想解决的学习问题，以及能检验的成果。
- 已有背景、熟悉内容和当前卡点。
- 教材、课程、论文或项目材料。
- 影响安排的期限与可用时间。
- 解释顺序、公式深度、节奏、反馈方式和熟悉的类比领域。
- 研究模式中的核心问题；课程模式可以没有研究问题。

通常少量短轮次即可开始。已说过的内容不重复询问；可以回答“不确定”“跳过”“先学，以后补”。你直接发来紧急题目或材料时，可以先解决本次学习目标，再补充画像。

这里的个性化指教学与互动偏好，不做人格或心理诊断。用户自述、实际学习表现和暂定建议分别记录。你说“我觉得懂了”不会直接把掌握度升到高等级，也不会预填你没有犯过的错。

自动维护的文件包括：

| 文件 | 用途 |
|---|---|
| `meta/learner_profile.json` | 画像唯一事实源 |
| `socrates/learner_profile.md` | 给教学模式读取的画像摘要 |
| `meta/core_questions.md` | 用户自己的核心研究问题，Q 编号稳定 |
| `meta/profile_log.md` | 画像更新记录 |

后续说“修改画像”“换目标”“我今天只有 15 分钟”“别用这个类比”即可更新相关内容。更换目标保留过去的笔记、进度和课程记录。中断初始化后，新聊天会读取已答内容与下一待问问题。

## 3. 与 Obsidian 一起使用

### 新知识库：共用同一文件夹

1. 在 Obsidian 中选择“打开文件夹作为仓库”。
2. 选择**本文件夹**。
3. Codex 也打开该文件夹作为项目。

Codex 保存 Markdown 笔记，Obsidian 自动反映外部文件变更。笔记中的 `[[链接]]`、标签、属性和公式按 Obsidian 支持的格式组织。这样不需要额外同步脚本，也不需要让 AI 操作 Obsidian 的界面。[Obsidian 数据存储说明](https://obsidian.md/help/data-storage)、[内部链接说明](https://obsidian.md/help/links)

可以让 Codex 更新目录、整理概念与论文页、补充关联、记录错题，或检查破损链接和孤立笔记。Obsidian 负责浏览、编辑和关联展示；对话入口仍在 Codex。

### 已有 Obsidian 仓库

当前初始化助手只接受空目录或已识别的 GPT 知识库，**不会直接覆盖非空旧仓库**。接入已有仓库需要提供其本地路径，先检查笔记结构、链接、附件和现有配置，再决定目录映射或复制迁移。这个步骤尚未在你的实际 Obsidian 仓库上执行。

不要把整包覆盖到已有库，也不要在一个 vault 内另建嵌套 vault。整理已有库时保留 `.obsidian` 设置、附件和原有笔记；移动或重命名需同步维护所有关联引用。该版未提供 Obsidian 内的聊天面板，也未实现后台持续监控。需要整理时在 Codex 发出请求。

## 4. 四层学习路径

| 层次 | 内容 | 产物 |
|---|---|---|
| 摄取 | 论文、网页剪藏、课程材料 | `raw/` 不可变原料 |
| 结构化 | 提取概念、方法、证据与条件 | paper / concept 页和链接 |
| 命题化 | 研究断言、开放问题、跨概念关联 | claim / question / connection 与证据状态 |
| 内化 | 对话、讲解检验、独立练习与纠错 | 学习进度、错题、掌握度与下一步 |

研究学习使用七步：全局定位 → 问题 → 精确命题 → 假设 → 反例 → 核心研究问题重整合 → 全局重整合。

课程学习使用六步循环：最小概念 → 例题 → 独立练习 → 纠错 → 错题日志 → near-transfer 变式题。

三套等级分别保留：论文阅读 **L0–L4**、课程掌握 **L0–L5**、提示阶梯 **0–4**。提示第 3 级只展示卡住的一步，第 4 级才展示完整解并给变式。独立作答是掌握度证据，读过或入库不等于学会。

## 5. 常用请求

| 你说 | 系统执行 |
|---|---|
| ingest 这篇论文，我后面再看 | 停车场：轻量阅读任务，不深读、不建整批概念页 |
| 带我读 / 我想学习这篇论文 | 阅读任务、论文主线、至多三个阻塞概念、黑箱边界，再互动学习 |
| 正式 ingest 这篇论文 | 读全文，维护论文、概念、命题、问题、连接、索引与日志 |
| 把这个 idea 放进系统 | 登记 hypothesis 或开放问题，给出下一步 |
| 帮我判断这个 idea 有没有人做过 | 检索维度与关键词、最近邻工作、证据化判断 |
| 帮我 ingest 这节课 | 课程图、主题页、题库和课程日志 |
| ingest 这节课然后教我 | 先整理，再诊断和分级提示教学 |
| 我逃课了，帮我补这节 | 本次目标、前置知识树、诊断与补课优先级 |
| 帮我准备这次作业 | 相关主题、薄弱项、类似练习和提示阶梯 |
| 用 Socrates 模式问我 | 从已有知识逐步追问，一次一问、等待回答 |
| 我觉得我懂了，考我 | 先出题，回答后评分与错误分类 |
| 用 Feynman 模式检验这个概念 | 你讲解，AI 扮演零基础同学追问 |
| 本周复盘 | 本周成果、主要错误、混合复习题与下周优先级 |
| 帮我整理系统 | 链接、索引、孤立页、命题证据、概念欠账和 Q 覆盖检查 |
| 帮我记录这次修改 | 按类型更新系统变更或迁移日志 |
| 继续上次学习 / 修改画像 | 文件状态续接 / 增量个性化更新 |

操作匹配用户意图，不要求背命令。一次教整门课时先看文件名和已有地图，再选择一个子主题，不一次深读所有材料。

## 6. 文件结构与保存

```text
personal-knowledgebase-gpt-kit/
├── README.md / START-HERE.md
├── AUDIT.md / MIGRATION.md / VALIDATION.md
├── install-plugin.ps1
├── marketplace/                       插件源，安装后保留
└── knowledgebase/                     在 Codex 和 Obsidian 打开的目录
    ├── AGENTS.md / .agents/skills/     入口与教学技能
    ├── raw/                          原始材料，只读不改
    ├── wiki/                         研究笔记、命题、问题、连接、任务、概念欠账
    ├── courses/                      各课程地图、题库、错题、掌握度和复盘
    ├── socrates/                     画像摘要、当前进度、教学改进、历史会话
    ├── templates/                    原版 13 个模板 + connection 模板
    ├── meta/                         画像事实源、核心问题、系统记录与备份
    ├── tools/                        本地保存助手
    └── temp/                         本次会话临时文件
```

研究操作写 `wiki/log.md`，课程入库写 `courses/log.md`，实际解题表现写对应课程的 `mastery_tracker.md` / `error_log.md`，对话与下一起点写 `socrates/progress.md`。约 200 行后将旧会话归档，读取历史按需进行。

将自己的论文放入 `raw/papers`，网页剪藏放入 `raw/clips`，课程材料放入 `raw/courses/<课程>`，或在聊天中指明材料路径。AI 对已经存在的原料只读，生成的笔记归对应成品目录。

画像覆盖前自动备份，保存失败会尝试回滚；进程意外中止会保留锁和事务清单供核对恢复。**备份机制主要覆盖画像批次，不等于每篇知识笔记都自动有完整版本历史。** 一般笔记由 Codex 按工作流维护，重要迁移先复制并验证。

只有工具写入且回读成功，系统才应称“已保存”。权限或工具失败时会说明尚未落盘。提供的 `.gitignore` 默认忽略学习数据；它不负责磁盘加密，也不能让曾提交过的数据自动消失。

## 7. 能确认到什么程度

- 已逐文件对照核心工作流与教学协议，原版 13 个模板均保留，新增一个连接模板。
- 四模式、原 13 个自然语言别名、研究七步、课程六步、提示阶梯、费曼与考查模式均有对应实现指令。
- 10 项真实文件行为测试通过，覆盖画像续接、历史保留、路径边界、原料不变、备份、失败回滚和链接检查。
- 本地插件在隔离 Codex 配置中成功安装并识别；最终版本见验证记录。
- 本次未改动原 Claude 文件夹，原 MIT 版权声明保留。

原版本身是由模型执行的文件工作流，不是能保证每轮输出完全一致的确定性教学程序。当前验证能支持“功能与路径完整迁移”，还不能支持“两个模型教学效果完全相同”。完整真实教学、多篇扫描 PDF、你的现有 Obsidian 库及第三方 Obsidian 插件行为，仍需实际使用验证。

阅读全文、联网检索、OCR 和公式预览受宿主能力影响。全文未读到时不得称完整入库；没检索到先例不证明创新；无搜索工具时先给检索计划并标记待核验。

## 8. 常见问题

**要同时开 Claude 吗？** 不需要。本版使用 Codex 的 GPT 与文件工具。

**关闭聊天会丢失进度吗？** 已成功写入文件的记录可在下次读取；未保存的聊天内容不能当成可靠进度。

**能自动改 Obsidian 中的笔记吗？** 在同一文件夹且具备文件权限时，Codex 按你的请求编辑 Markdown。当前没有后台自动整理或 Obsidian 内聊天按钮。

**可以把原版目录直接改成 GPT 版吗？** 当前包提供单独的新工作区。旧库迁移应另做目录核对和复制验证；不要用初始化命令覆盖已有资料。

**“帮我整理系统”会删除资料吗？** 默认先检查并报告。删除、移动或大规模合并需明确指令；必要修复遵循用户已有授权。
